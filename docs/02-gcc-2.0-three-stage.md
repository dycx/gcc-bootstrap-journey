# GCC 2.x: The Canonical 3-Stage Bootstrap (1992-2003)

## Historical Context

GCC 2.0 was released in 1992, representing a major leap forward. It introduced:

1. **autoconf-based configuration** — no more manual config.h copying
2. **The 3-stage bootstrap** — the formal, verified self-hosting process
3. **C++ frontend** — GCC could now compile C++ code
4. **Objective-C frontend**
5. **Better optimizer** — more optimization passes

Richard Stallman was still the primary maintainer, with significant contributions
from John Gilmore, David Henkel-Wallace, and others.

## The 3-Stage Bootstrap (Introduced in 2.x)

This was the most important innovation in GCC 2.x. It's still used today.

### Why 3 Stages?

The problem with a 2-stage bootstrap (build with system compiler, then rebuild
with your new compiler) is that you can't verify correctness:

```
Stage 1: system cc → gcc_stage1
Stage 2: gcc_stage1 → gcc_stage2

Is gcc_stage2 correct?
  - It compiled itself successfully, so it seems to work...
  - But what if gcc_stage1 has a bug that makes gcc_stage2
    also buggy, but in a way that still compiles itself?
  - This is the "fixed-point bug" — a buggy compiler that
    produces a buggy copy of itself that works identically.
```

The 3-stage process breaks this cycle:

```
Stage 1: system cc → gcc_stage1
Stage 2: gcc_stage1 → gcc_stage2
Stage 3: gcc_stage2 → gcc_stage3

Compare: gcc_stage2 objects vs gcc_stage3 objects
  If IDENTICAL → compiler reached a true fixed point
  If DIFFERENT → there's a bug somewhere
```

### The Detailed 3-Stage Process

```
┌─────────────────────────────────────────────────────────┐
│                    STAGE 1                               │
│  Input:  GCC source code (.c files)                     │
│  CC:     System compiler (cc, old gcc, etc.)            │
│  Output: gcc/stage1/xgcc, gcc/stage1/cc1                │
│          gcc/stage1/libgcc.a                            │
│                                                         │
│  What happens:                                          │
│  - All .c files compiled with system compiler           │
│  - Object files placed in gcc/stage1/                   │
│  - Linked into the xgcc driver and cc1 compiler         │
│  - libgcc.a built (runtime support library)             │
└─────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────┐
│                    STAGE 2                               │
│  Input:  Same GCC source code (.c files)                │
│  CC:     gcc/stage1/xgcc (the Stage 1 compiler)        │
│  CFLAGS: -O2 -g (BOOT_CFLAGS)                          │
│  Output: gcc/stage2/xgcc, gcc/stage2/cc1                │
│          gcc/stage2/libgcc.a                            │
│                                                         │
│  What happens:                                          │
│  - All .c files recompiled with Stage 1 compiler        │
│  - Uses optimized flags (-O2 -g)                        │
│  - This compiler is "GCC-built-GCC"                     │
│  - Object files placed in gcc/stage2/                   │
└─────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────┐
│                    STAGE 3                               │
│  Input:  Same GCC source code (.c files)                │
│  CC:     gcc/stage2/xgcc (the Stage 2 compiler)        │
│  CFLAGS: -O2 -g (BOOT_CFLAGS)                          │
│  Output: gcc/stage3/xgcc, gcc/stage3/cc1                │
│          gcc/stage3/libgcc.a                            │
│                                                         │
│  What happens:                                          │
│  - All .c files recompiled with Stage 2 compiler        │
│  - This should produce IDENTICAL output to Stage 2      │
│    if the compiler is correct                           │
└─────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────┐
│                    COMPARE                               │
│                                                         │
│  diff -r gcc/stage2/ gcc/stage3/                        │
│  (or objcmp for binary comparison)                      │
│                                                         │
│  If all files match → PASS → install stage3             │
│  If any differ      → FAIL → compiler bug detected      │
└─────────────────────────────────────────────────────────┘
```

### Why This Works (The Fixed-Point Argument)

If the compiler is correct:
- Stage 2 = compile(source, stage1)
- Stage 3 = compile(source, stage2)

If stage1 and stage2 are both correct compilers, they should produce
the same output for the same input. So stage2 and stage3 objects
should be identical.

If stage1 has a bug:
- Stage 2 = compile(source, buggy_stage1) = buggy_stage2
- Stage 3 = compile(source, buggy_stage2) = ???

If the bug is "stable" (buggy_stage2 produces itself), then stage2 == stage3
and the bug is undetectable. But in practice, most compiler bugs are NOT
stable — they produce different bugs each generation. So the 3rd stage
catches almost all bugs.

### Build Instructions (GCC 2.95)

```bash
# Download
wget https://ftp.gnu.org/gnu/gcc/gcc-2.95.3/gcc-2.95.3.tar.gz
tar xzf gcc-2.95.3.tar.gz
cd gcc-2.95.3

# Configure (autoconf-based now!)
./configure --prefix=/usr/local

# 3-stage bootstrap
make bootstrap

# Or manually:
make stage1      # Build with system compiler
make stage2      # Build with stage1
make stage3      # Build with stage2
make compare     # Compare stage2 vs stage3
make install     # Install stage3
```

### Makefile Targets (GCC 2.x)

```bash
make              # Build stage1 only (for development)
make bootstrap    # Full 3-stage bootstrap
make bootstrap-lean  # Bootstrap, remove intermediate files
make stage1       # Just stage 1
make stage2       # Just stage 2
make stage3       # Just stage 3
make compare      # Compare stage2 and stage3
make install      # Install from stage3
```

## Key Technical Changes

### 1. autoconf
The `./configure` script automatically detects:
- Host machine type
- Available system libraries
- System compiler capabilities
- Header file locations

No more manual config.h copying!

### 2. Machine Descriptions (RTL)
GCC 2.x expanded the Register Transfer Language (RTL) system:
- Machine descriptions (.md files) define each target
- The compiler generates code by matching RTL patterns
- Adding a new target = writing a new .md file

### 3. C++ Frontend
GCC 2.x added C++ compilation via `cc1plus`:
```bash
gcc -x c++ file.cpp   # Compile C++
g++ file.cpp           # The C++ driver
```

### 4. Better Optimizer
- Basic block analysis
- Loop optimization
- Common subexpression elimination
- Instruction scheduling

## Significance

GCC 2.x established the **canonical bootstrap process** that's still used today.
The 3-stage bootstrap with comparison is the gold standard for compiler
verification. Every major compiler that self-hosts uses some variation of this.

## Limitations

- Still written entirely in C
- No Tree-SSA (optimization on AST, not just RTL)
- Limited interprocedural optimization
- No link-time optimization (LTO)
