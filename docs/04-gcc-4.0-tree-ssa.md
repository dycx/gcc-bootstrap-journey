# GCC 4.x: Tree-SSA Revolution (2005-2012)

## The Tree-SSA Framework

GCC 4.0 (released 2005) introduced the **Tree-SSA** optimization framework,
the biggest architectural change since GCC 3.0.

### What is SSA?

**Static Single Assignment (SSA)** form means every variable is assigned
exactly once. When a variable has multiple assignments, new "versions" are
created:

```c
// Original code
x = 1;
y = x + 2;
x = 3;
z = x + y;
```

```c
// SSA form
x_1 = 1;
y_1 = x_1 + 2;
x_2 = 3;
z_1 = x_2 + y_1;
```

### Why SSA?

SSA makes many optimizations trivially easy:

1. **Constant Propagation**: If x_1 = 5, replace x_1 with 5 everywhere
2. **Dead Code Elimination**: If x_1 is never used, delete the assignment
3. **Common Subexpression Elimination**: If two computations are identical, merge them
4. **Value Numbering**: Assign unique IDs to equivalent computations

### Key Improvements in 4.x

1. **Tree-SSA**: All major optimizations now work on trees, not RTL
2. **Better Inlining**: More aggressive, guided by IPA (Interprocedural Analysis)
3. **Link-Time Optimization (LTO)**: First experimental support
4. **Auto-vectorization**: Automatic SIMD vectorization
5. **Fortran Frontend Rewrite**: New Fortran 95 frontend

### Build Instructions (GCC 4.9)

```bash
# Download
wget https://ftp.gnu.org/gnu/gcc/gcc-4.9.4/gcc-4.9.4.tar.bz2
tar xjf gcc-4.9.4.tar.bz2
cd gcc-4.9.4

# Download prerequisites (GMP, MPFR, MPC, ISL)
./contrib/download_prerequisites

# Out-of-tree build
mkdir objdir && cd objdir
../gcc-4.9.4/configure --prefix=/usr/local \
    --enable-languages=c,c++,fortran \
    --disable-multilib \
    --enable-bootstrap

# Standard 3-stage bootstrap
make -j$(nproc) bootstrap

# Profiled bootstrap (PGO-optimized)
make -j$(nproc) profiledbootstrap
```

## The C++ Self-Hosting Decision (GCC 4.8, 2012)

### The Big Change

In 2012, GCC 4.8 was released with a revolutionary change: **GCC itself was
now written in C++, not C**.

This was controversial because:
1. It required a C++ compiler to bootstrap GCC
2. It changed the bootstrap dependency chain
3. Some developers opposed the change

### Why C++?

The GCC developers argued:
1. **Better abstractions**: Classes, templates, RAII for resource management
2. **Less boilerplate**: Less manual memory management
3. **Better error detection**: Type safety, const correctness
4. **Developer productivity**: Modern language features
5. **Self-hosting as proof**: If GCC can compile itself in C++, the C++ frontend works

### The Bootstrap Problem

Before GCC 4.8:
```
Any C compiler → GCC (written in C) → GCC (self-hosted)
```

After GCC 4.8:
```
Any C++ compiler → GCC (written in C++) → GCC (self-hosted)
                ↑
        Now you need a C++ compiler!
```

This means:
- You can't bootstrap GCC 4.8+ with just a C compiler
- You need an existing C++ compiler (like an older GCC, or Clang)
- The bootstrap chain now requires C++ capability

### How GCC Handles This

The `make bootstrap` process in GCC 4.8+ works the same way, but:

1. Stage 1 uses whatever C++ compiler is available (`g++`, `clang++`)
2. Stage 2 uses Stage 1's `cc1plus` to compile GCC's C++ sources
3. Stage 3 uses Stage 2's `cc1plus` to compile again
4. Comparison verifies Stage 2 == Stage 3

## Significance

Tree-SSA made GCC competitive with commercial compilers. The C++ self-hosting
decision modernized the codebase and proved that a complex system compiler
can be written in its own language.
