# GCC 1.0: The Beginning (1987)

## Historical Context

Richard Stallman (RMS) started writing GCC in 1984 as part of the GNU Project.
The first public release, GCC 1.0, came in March 1987.

Before GCC, Unix C compilers were proprietary and expensive. RMS wanted a
free (as in freedom) compiler that anyone could use, modify, and distribute.

## How GCC 1.0 Worked

### Language & Architecture
- Written entirely in **C** (K&R C, not ANSI C yet)
- Only supported **C** language (no C++, no Fortran)
- Targeted **VAX** and **Sun** workstations (68000-based)
- ~110,000 lines of code

### Build System
There was **NO autoconf, NO configure script, NO make bootstrap**.

The build was entirely manual:

```bash
# 1. Copy the right config file for your machine
cp config-sun3.h config.h
cp tm-sun3.h tm.h
cp xm-sun3.h xm.h

# 2. Edit the Makefile to set paths
#    CC = /usr/bin/cc
#    CFLAGS = -O
#    prefix = /usr/local

# 3. Build
make
```

### The Bootstrap Problem (1987)

In 1987, there was no `make bootstrap` target. If you wanted to build GCC
and then use it to compile itself, you did it manually:

```bash
# Step 1: Build GCC with the system compiler
make CC=/usr/bin/cc

# Step 2: Use the new GCC to rebuild itself
make clean
make CC=./gcc

# Step 3: Compare (manually, or trust it)
# Step 4: Install
make install
```

This was the **proto-bootstrap** — a manual 2-step process. There was no
formal verification (no objcmp, no stage comparison).

### The Design Decision

GCC 1.0 was designed to be **self-hosting from day one**. RMS wrote the
compiler in a subset of C that any reasonable C compiler could handle. This
meant:

1. No ANSI C features (only K&R C)
2. No complex macros
3. No function prototypes
4. Minimal dependencies

### Key Files in GCC 1.0

```
gcc-1.0/
├── Makefile              # The ONLY build file
├── config.h              # Target machine config (copy from config-*.h)
├── tm.h                  # Target machine header (symlink)
├── xm.h                  # Host machine header (symlink)
├── gcc.c                 # The GCC driver program
├── toplev.c              # Top-level compiler logic
├── local-alloc.c         # Local register allocation
├── global.c              # Global register allocation
├── reload.c              # Register reloading
├── reload1.c             # More reloading
├── optabs.c              # Operation tables
├── expmed.c              # Expression medicine (?)
├── expr.c                # Expression handling
├── stmt.c                # Statement handling
├── parse.y               # Parser (yacc grammar)
├── scan.l                # Scanner (lex)
├── c-parse.y             # C-specific parser
├── c-lex.l               # C-specific lexer
├── tree.h                # Tree (AST) definitions
├── rtl.h                 # Register Transfer Language defs
├── genconfig.c           # Generate machine description
├── gencodes.c            # Generate code patterns
├── gen-protos.c          # Generate prototypes
├── md/                   # Machine descriptions
│   ├── vax.md
│   ├── m68k.md
│   └── ...
└── config/               # Machine-specific configs
    ├── config-vax.h
    ├── config-sun3.h
    └── ...
```

### The Compilation Pipeline (1987)

```
Source Code (.c)
    │
    ▼
┌─────────────┐
│  Scanner     │  c-lex.l → tokens
│  (Lexer)     │
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  Parser      │  c-parse.y → AST (trees)
│  (Yacc)      │
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  RTL Gen     │  AST → Register Transfer Language
│              │
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  Optimizer   │  Simple optimizations on RTL
│              │
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  Code Gen    │  RTL → Assembly (.s)
│              │
└──────┬──────┘
       │
       ▼
  Assembly Output
```

### Optimization Levels (1987)

- `-O` or `-O1`: Basic optimizations (dead code elimination, constant folding)
- No `-O2` or `-O3` yet
- No `-Os` (size optimization) yet

## Significance

GCC 1.0 was revolutionary because:
1. First **free** C compiler
2. Designed to be portable (machine descriptions via .md files)
3. Designed to be self-hosting (bootstrappable)
4. Started the GNU Project's compiler infrastructure

## Limitations

- Only C language
- Only a few target architectures
- Very basic optimizer
- Manual build process
- No formal bootstrap verification
- K&R C only (no ANSI C)
